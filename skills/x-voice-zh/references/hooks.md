# 钩子类型库

拆爆款时先判断它用的是哪种钩子，再决定能不能用用户自己的事转写。**下面的骨架是通用句式，示例是虚构的。**
`extract_skeleton.py` 用规则做初判，可能判错，请对照原帖复核。

| 类型 | 骨架（`__` 是要换成你自己的事实） | 虚构示例 | 转写前提 |
|---|---|---|---|
| 下判断 | 一句明确的判断，后面一两句给依据 | 做小工具最贵的不是服务器，是没人用的功能。 | 你对这件事有亲身看法，且有依据 |
| 报数字 | 开头直接报一个真实数字，再说怎么来的 | 上线 11 天，付费用户 38 个。 | 数字是你自己的，已核对 |
| 拿出成品 | 先把做好的东西摆出来，再说过程或坑 | 终于做完了 __，能直接玩/用。 | 你真的有成品，可以给出演示 |
| 坦白 | 先认一个失败或不光彩的事，再说学到什么 | 说实话，我第一个产品 3 个月 0 付费。 | 事是真的发生过 |
| 报痛点 | 说一个大家都有的具体麻烦，再问或给办法 | 卡了我三天：支付回调老丢。 | 你真遇到过，问题具体 |
| 打时间差 | 用「多久做到什么」或「以前现在」做对比 | 从 0 到第一个付费用户，9 天。 | 两头的时间和结果你都有记录 |

## 怎么挑
- 想要**回复**：用户处境 + 一个读者答得出的具体问题（坦白、报痛点）。
- 想要**收藏**：给读者能存起来用的东西（命令、清单、模板、账本数字）；骨架里要有「可存内容」，别只学语气。
- 新闻转述 + 金句收尾的帖子，通常数据差，也最像 AI，不转。

## 转写时保留什么、换什么
- 保留：钩子类型、行数、开头的力度、有没有配图/视频、有没有「评论区放完整版」。
- 换掉：事实、数字、措辞、开头的词、表情习惯（按用户画像）。
- 不要保留：原帖的独特句式、原帖的比喻。
